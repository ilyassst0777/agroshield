# AgroShield AI — прототип с NASA POWER и SoilGrids WCS

Новая сборка для **Field Shift: Adapting Farms with NASA Data**, Северо-Казахстанская область. Два процесса: React/Vite в браузере и локальный Python API, который обращается к NASA POWER и SoilGrids WCS. Реальные ответы API не подменяются демонстрационными цифрами.

## Требования

- **Node.js 22 или новее** (Vite 8 требует современные версии Node.js).
- **Python 3.11 или 3.12**, установленный с опцией **Add Python to PATH**. Для геобиблиотек `rasterio` и `pyproj` предпочтительно Python 3.12.
- Доступ к Интернету для базовой карты, NASA POWER и ISRIC SoilGrids.
- Windows PowerShell, две открытые вкладки терминала.

## Первый запуск на Windows

После распаковки проекта в папку `agroshield` откройте PowerShell в этой папке.

**Окно 1 — Python API**:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r server\requirements.txt
.\.venv\Scripts\python.exe -m uvicorn server.app:app --reload --host 127.0.0.1 --port 8000
```

Если Python 3.12 не установлен, выполните `py -3 -m venv .venv` с подходящей версией 3.11+.

**Окно 2 — React/Vite**:

```powershell
npm install
npm run dev
```

Откройте адрес из Vite, обычно **http://localhost:5173/**. Проверка Python: **http://127.0.0.1:8000/api/health**.

Если PowerShell выдаёт `vite не является командой`, сначала выполните `npm install`. Старую `node_modules` от других компьютеров копировать не надо.

## Как получить данные для поля

1. Откройте «Мои поля» → выбранное поле. При необходимости нарисуйте границы через «Изменить границы». Границы сохраняются как GeoJSON, площадь вычисляется по координатам.
2. «Данные поля» → «Климат и вода» → **Загрузить NASA**. Python API запрашивает многолетние месячные ряды NASA POWER и рассчитывает май–август, отклонение от нормы 1991–2020, температуру, радиацию, влажность и ветер. Модельная влажность `GWETROOT` запрашивается отдельно, поскольку доступность параметров отличается.
3. «Данные поля» → «Почва» → **Загрузить почву**. Python API обращается к SoilGrids WCS 2.0.1, получает пять растров GeoTIFF по глубине 5–15 см, рассчитывает медианные значения по ячейкам, попавшим в контур (для маленьких полей — ближайшую ячейку), переводит pH, органический углерод, песок, пыль и глину в подписанные единицы.
4. «Документы» → загрузите CSV/XLSX/PDF. CSV/XLSX покажут предпросмотр с листом, строкой и названием поля. В историю переносятся **только строки с точным сопоставлением**, после вашего подтверждения; PDF хранится как оригинал, без автоматической подстановки лабораторных значений.
5. «AI-рекомендации» → три стратегии, предварительный выбор системы, научные ссылки, риски, кнопка черновика и утверждение фермером.

## Важные особенности реализации

- Браузер обращается к `/api/...`; Vite перенаправляет запросы на `127.0.0.1:8000` (см. `vite.config.js`).
- SoilGrids REST не используется. Сервис WCS выдаёт **GeoTIFF**, которые обрабатываются сервером с помощью `rasterio`, `shapely` и `pyproj`. Никаких запросов WCS прямо из браузера.
- Когда WCS или NASA недоступны, приложение показывает текст ошибки; **значения не подделываются**. ISRIC WCS может отвечать медленно или быть временно недоступен.
- Кэш NASA и почвы сохраняется в `server/cache/`; импортированные оригиналы — в `server/storage/accepted/`. Эти папки не включены в ZIP.
- История полей и решений хранится в браузере (`localStorage`). Предусмотрена миграция существующих данных из ключа `agroshield-farmer-v3` в `agroshield-farmer-v4`. Для долгосрочного хостинга потребуется серверная БД, права доступа и резервное копирование.
- Автоматическая проверка гербицидов **не ищет слова в свободном тексте**. В анкете есть отдельный ответ «Да / Нет / Не знаю». Расчёт реального последействия по этикеткам препаратов ещё не реализован.
- **Три сценария — пример качественного агрономического движка**, а не научная валидация оптимального севооборота. Загрузка NASA и почвы улучшает доказательную базу, но не заменяет проверку сортов, гербицидов, сроков и затрат. Результаты сохраняются как решение фермера; отдельного статуса «сертифицировано» нет.

## Проверка кода

```powershell
npm run lint
npm run build
.\.venv\Scripts\python.exe -m pip install pytest httpx
.\.venv\Scripts\python.exe -m pytest -q server\tests
```

**Проведено в среде подготовки:** исходники React прошли ESLint и синтаксическую проверку; 4 Python-теста прошли с мок-ответами. **Фактические запросы к NASA/SoilGrids и сборка Vite на Windows здесь не проверены**: у среды подготовки нет сетевого доступа к этим внешним API и нет совместимых Linux-бинарников старой папки `node_modules`. Проверьте их локально по инструкции выше.
